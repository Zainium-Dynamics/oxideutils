# OxideUtils release process

This is the reusable checklist for any OxideUtils release tag.

Supported tag examples:
- `v0.1.0`

## 1) Pre-flight checks

Run from repo root:

```bash
cargo metadata --no-deps
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo build --workspace --release
```

## 2) Version and changelog

- Ensure workspace version in `Cargo.toml` matches intended release.
- Ensure `CHANGELOG.md` has a section for that version.

Example check (replace with your target):

```bash
VERSION="0.1.0"
rg -n "version = \"$VERSION\"|$VERSION" Cargo.toml CHANGELOG.md
```

## 3) Commit (single-author)

```bash
git add Cargo.toml .gitlab-ci.yml CHANGELOG.md docs/release-process.md docs/README.md
git commit -m "release: prepare $VERSION"
```

Do not add any `Co-authored-by:` trailer.

## 4) Create annotated tag

```bash
git tag -a "v$VERSION" -m "OxideUtils v$VERSION"
git show --no-patch --pretty=fuller "v$VERSION"
```

## 5) Push

```bash
git push origin main
git push origin "v$VERSION"
```

Tag push triggers GitLab release job automatically.

## 6) CI release output

The GitLab release job publishes full workspace source (tracked files) as:
- `dist/oxideutile-<version>.tar.zst`
- `dist/oxideutile-<version>.sha256`

Notes:
- archive is generated by `git archive`
- generated folders like `target/` are not included

## 7) Post-release checks

```bash
VERSION="0.1.0"
sha256sum -c "oxideutile-${VERSION}.sha256"
```

If there is an issue, fix and cut a new patch tag (for example `v0.1.1`).
Do not move an existing pushed tag.
